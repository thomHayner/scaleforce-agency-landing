## Context

Setting up a place to capture architectural decisions for this repo so they can be referenced and audited later. Establishes the convention used by the `adrs-write` skill in future sessions.

## Decision

Adopt `docs/adr/` with markdown + YAML-frontmatter ADRs. Use date-based slugs (`ADR-YYYY-MM-DD-kebab-case-slug.md`) instead of sequential numbers.

## Alternatives considered

- **Sequential ADR numbering** — rejected: collisions across parallel branches and parallel sessions.
- **Pure YAML or JSON files** — rejected: ADRs are prose-heavy; markdown is better for context and rationale.
- **Capture decisions in commit messages or wiki only** — rejected: low discoverability and no fixed schema.

## Consequences

- **Positive:** standard discoverable location for decisions; queryable via frontmatter.
- **Negative:** small upfront convention overhead per decision.
- **Follow-ups:** future sessions can use the `adrs-write` skill to extract ADRs from conversations.
